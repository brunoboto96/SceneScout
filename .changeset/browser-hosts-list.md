Add `browserHosts` to the operator config (and `SCENESCOUT_BROWSER_HOSTS`): the only hosts the browser may reach besides the app's own. With a list set, every request to another host is refused before it leaves the machine, in every mode: page loads and the later hops of their redirects, scripts, styles, images, frames, workers, fetch and XHR and their redirects, and WebSockets (in Firefox and WebKit, which route no redirect hop, through a Content-Security-Policy each document is given beside its own). A refused page load leaves the page where it was, an attach whose start address redirects off the list is not attached and names the host, and each refusal is reported in a `BROWSER-HOSTS blocked` notice. The `strict` preset now sets `browserHosts: []`, the app's host alone. `scenescout policy explain` and `scenescout config explain` show the list.

**If your config file sets `"preset": "strict"`, this changes what your runs load.** The browser now reaches nothing but the app's own host, so a page's fonts, scripts, images or frames from a CDN or another service are refused, WebRTC and WebTransport are taken from the page, and an app whose start address redirects to another host (a single sign-on provider, for one) is not attached. Name the hosts your app needs beside the preset, for example `{"preset": "strict", "browserHosts": ["cdn.example.net", "login.example.com"]}`. The sign-in window `scout_login` and `scenescout login` open is not held by the list, but the runs after it are: an app that sends a saved session back to its sign-on provider to renew it needs that host listed too. Without a config file, or with one that sets neither the preset nor `browserHosts`, nothing changes unless you set the new `SCENESCOUT_BROWSER_HOSTS`.
