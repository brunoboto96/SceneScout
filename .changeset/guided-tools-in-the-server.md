Guided checks in the server. `scout_intake`'s form now asks the guided start: the address, what to check (sign-up and sign-in, forms, broken pages, a phone-sized screen, a journey, tickets), how you sign in, how careful to be (Look only, May submit forms, May create test data) and how thorough, and returns a guided plan. Two new tools: `scout_guided_plan` builds or reads a plan, and `scout_guided_confirm` asks the person, in a form the server shows them, to confirm a care level that writes (with a code to type for test data); the agent can call it but cannot answer it, and a declined, failed or absent form leaves the plan unaccepted. Once a guided plan exists, `scout_attach` above `observe` needs an accepted plan's `planId`, in no mode above the plan's and on its site; while a plan is open, `readPosts` and `trustedEmbeds` are refused, and a confirmation covers one check, so a plan no session carries any more is confirmed again. Lane briefs pass the planner's `planId` on. `scout_session {area}` names the area a session is checking. Look only's wording now says exactly what it lets through: a search still runs, and a link that changes something when opened is not stopped.
