`scenescout policy explain <METHOD> <URL>` prints whether the write policy would let one request out in each mode (or the one given with `--mode`), and the rule that decided, using the same functions the running engine judges requests with; `--body file` and `--header "Name: value"` add a body and headers such as a method override, and it reads the server's policy variables from its environment and the config file's `readPosts`. It sends nothing, and prints the address without a user name, password or token. With `SCENESCOUT_REFUSE_DESTRUCTIVE_GETS=1`, a page load of `/things/9/void`, `/requests/4/reject`, `/approve?token=…` or `/account/close` is now refused as a destructive command (`void`, `reject` and `approve` as a whole path segment; `close` after a record's id or the user's own account), and the engine no longer reloads such an address itself after a refused form. The Safety model page now says plainly to use `observe` for real data, lists what each mode rests on, and separates masking by a field's own attributes (a guarantee) from recognising secrets by name or shape (best effort).
