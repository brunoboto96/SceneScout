The redaction hides more of what a run keeps. A short or letters-only value set against a secret's name (`password: hunter2`, `client_secret=…`), a PIN or sign-in code after its word (`PIN 4821`, `PIN code 4821`, `code 482913` or `482 913`, `OTP 482913`), letters-only bearer tokens, `sk-ant-`, Slack `xox…`, Google `AIza…`, `glpat-` and `npm_` keys, private-key PEM and PGP blocks, and `?code=`, `X-Amz-Signature=` and `sessionid=` values are now redacted. So are email addresses written with `(at)` and `(dot)`, with a quoted local part or at an IP literal, card numbers split by slashes or by separators with spaces around them, Maestro's 12-digit cards, and phone numbers after `Call`, `WhatsApp`, `Contact`, `Ph:` or `T:`. A repository's SSH address (`git@host:team/repo.git`), `Password: required`, `Token: revoked`, a value shown as `••••`, an error, postal, coupon or invoice code, and names about a secret (`token_count`, `otp_enabled`, `Password strength`) stay readable. More field names count as secret (`pass`, `pw`, a code on its own, an access, SSH, signing or license key, a session id, credentials), and a password field stays masked, in the log and in pictures, after a show-password toggle makes it text. The guided choices refuse a sign-in written as `bob / …`, `bob:…`, `pass …` or "enter … when", and accept a value given to test a password field ("test the password strength meter with …"). A store is cleaned once more with the new redaction the first time it is opened.
