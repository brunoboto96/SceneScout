Security: `scout_upload` and a run plan's upload step now refuse a file that looks like a credential, even inside the project: dotfiles and anything in a hidden folder (`.scenescout/fixtures/` aside), `.env` and `.env.*`, SSH keys (`id_rsa`, `id_ed25519`, other `id_…` files with no extension but `.pub`, and copies such as `id_rsa.bak`), `*.pem`, `*.key`, `*.p8`, `*.p12`, `*.pfx`, `*.ppk`, `*.jks`, `*.keystore`, `*.asc`, `*.kdbx`, `.npmrc`, `.netrc`, `.pgpass`, and anything under `.ssh`, `.aws`, `.gnupg`, `.config`, `.kube` or `.docker`. The check runs on the path as given and on the file a symbolic link leads to, and reads a name as Windows opens it (`server.pem.` counts as `server.pem`). To upload such a file on purpose, list its exact absolute path in the server's new `SCENESCOUT_UPLOAD_ALLOW` setting; the agent cannot set it. Generated fixtures are unaffected. `scout_attach`'s `storageStatePath` must now be inside the project, its `.scenescout/auth/` included, and not under one of those secrets folders, unless the server's new `SCENESCOUT_STORAGE_STATE_ALLOW` lists the file. `--storage-state` for `check` and `ci` is still read wherever it is. A file that is not a valid storage state is refused without quoting any of its contents.
